# Сверка с предоставленным проектом — 20.10.2026

Использованы локальные исходные данные и сохранённые отчёты проекта пользователя.
Оригинальная программа не запускалась; проект не изменялся. Ни исходные файлы,
ни численные fixtures, координаты, названия объекта и результаты проекта
не включаются в публичный репозиторий. Здесь только методика и агрегаты.

## Результат сверки параметров

В выбранном каталоге результатов найдены 28 таблиц Cm/Um/Xm. После исключения
пяти отчётов по группам суммации остаются 68 пар «вещество–источник»:
49 точечных и 19 площадных. Из точечных 16 имеют температуру газа ниже
температуры воздуха и пока не поддерживаются ядром.

Сравнены 33 оставшиеся пары: 15 веществ, 14 идентификаторов источников,
19 уникальных физических конфигураций с учётом F, но без выброса и ПДК.
Это не 33 независимых проекта и не проверка всего поля концентраций.

| Интерпретация входа | Совпали Cm/ПДК, Um и Xm | Расхождения |
| --- | ---: | ---: |
| Скорость w0 буквально из текстового входа | 9 / 33 | 24 / 33 |
| Скорость w0 = 4 V1 / (π D²) из сохранённого расхода | 33 / 33 | 0 / 33 |

Во втором варианте совпали все 99 отдельных параметров с точностью печати
отчёта: ± половина последнего десятичного разряда, без дополнительного epsilon.
Формулы ядра и допуски не менялись.

Сверка повторена на базовом ядре без посторонних локальных изменений:
все решения PASS/FAIL совпали. В профиле по расходу три рассчитанных числа
отличаются не более чем на `1.14e-13` между сборками, поэтому побайтовое
равенство отчётов не заявляется. Прочитанные 138 файлов проекта повторно
проверены по SHA256 и остались неизменными.

Оба варианта вычисляются явно и сохраняются отдельно. Второй допускается
только когда восстановленная скорость лежит в интервале округления
напечатанной скорости. Это не подбор параметра по желаемому результату:
используются только V1 и D из входа, до сравнения с выходом.
Точность самих V1 и D и внутренняя арифметика оригинала не установлены.

Локальная структура DBF дополнительно показывает, что поле скорости имеет
два десятичных разряда, а поле расхода — семь. Поэтому отличие не следует
автоматически приписывать только текстовому экспорту. Совпадение при
восстановлении скорости из расхода — сильное свидетельство согласованности
этой интерпретации, но не доказательство внутреннего алгоритма ЭРА.

## Особенности чтения проекта

Новый `tools/project_source_fixture.py` читает выбранные файлы непосредственно
из каталога, без упаковки/распаковки и без исполнения оригинального ПО.
Проверяет границы путей, запрещает ссылки, ограничивает чтение, фиксирует
SHA256 каждого прочитанного файла. Выходы должны находиться вне оригинала.

- Имя каталога считается непрозрачным идентификатором, а не расчётным годом.
  Год/вариант/режим сверяются между заголовками отчётов.
- Короткий код источника связывается с полным кодом только при явно указанной
  уникальности в пределах предприятия; неоднозначность отвергается.
- ПДК сверяется между входом и результатом, выброс — с точностью печати.
- Сезон Max проверяется по управляющему файлу и отчётам. Руководство
  расчётного блока объясняет его как зиму для отрицательного условного знака
  высоты и лето для остальных. Поле WS не используется как признак зимы.
- В данной выборке все высоты положительные: использована летняя температура.
- Площадки, группы суммации и неподдерживаемые точечные источники получают
  явный статус пропуска, а не успешного сравнения.

Пример запуска (пути и каталог условные):

```sh
python tools/project_source_fixture.py /private/project \
  --folder 0000_0_1 --flow printed-speed \
  --cases /private/raw-cases.json --notes /private/raw-notes.json
python tools/project_source_fixture.py /private/project \
  --folder 0000_0_1 --flow stored-volume \
  --cases /private/volume-cases.json --notes /private/volume-notes.json
cargo run --locked --release --example archive_source_compare -- \
  /private/volume-cases.json /private/volume-comparison.json
```

Все выходные файлы создаются исключительно как новые. Формат происхождения
для каталога содержит `project_name` и `selected_files_manifest_sha256`.
Хеш вычисляется по списку `{member, sha256}`, отсортированному по member,
сериализованному JSON с отсортированными ключами и разделителями `,`/`:`.
Это хеш прочитанных файлов, не всего проекта. Сам Rust-сравниватель проверяет
формат метаданных, но не перепроверяет исходный каталог.

## Диагностическое повторение точки сетки

Для одного вещества без пропущенных источников и без фона выбран сохранённый
максимум сетки. При напечатанном ветре и восстановленной из расхода скорости
истечения отличие составило около `5.44e-11` мг/м³, или `0.0000531%`.

Этому результату **не присвоен статус PASS**: исходный расчёт использовал поиск
опасного ветра, а в CSV направление и скорость округлены. Двухметровый слой
рецептора остаётся явным предположением текущего ядра. Кроме того, координаты
входа и печатного отчёта могут иметь разную точность.

## Что эта сверка не подтверждает

Сохранённые отчёты не являются новым независимым запуском ЭРА; их актуальность
по отношению ко всему проекту не доказана. Пока не проверены полное поле,
оптимизация ветра, фон, здания, площадные источники, группы суммации и режимы
с отрицательной разностью температур. Нет оснований выпускать полноценный EXE.

Следующий приоритет по этому проекту — исследовать отрицательную разность
температур и площадные источники, затем расширять сверку поля при явно
зафиксированных настройках. Предыдущая узкая проверка по учебному архиву
описана [отдельно](ARCHIVE_SOURCE_VALIDATION.md).
