# Как проверяем совпадение с ЭРА

Сейчас в репозитории **нет эталонных выгрузок работающей ЭРА**.
Тесты по формулам и тесты нашего поиска не являются подтверждением
численного совпадения с оригиналом. USB-ключ не требуется для Rust-модуля,
но контрольные задачи оригинала должен рассчитать специалист с доступом
к лицензированной ЭРА. Передавать ключ нам не нужно.

## Что нужно получить от специалиста

Для каждой обезличенной задачи нужны:

1. Полная версия и сборка ЭРА, выбранная модель/методика расчёта.
2. Исходные данные источников, веществ, метеопараметров и расчётных точек
   с единицами, системой координат и направлениями ветра.
3. Все существенные настройки: фон, рельеф, здания, трансформация,
   группы суммации, высоты точек, коэффициенты, режимы работы источников.
4. Машиночитаемые результаты с максимально доступной точностью, а также
   протокол настроек. Скриншот полезен для контроля, но недостаточен для
   полноценного массового сравнения.
5. Идентификатор/хеш исходного экспорта, дату расчёта и точность округления.
   Персональные и коммерческие сведения в публичный репозиторий не включаем.

Сначала берём только режимы, поддержанные обеими программами: одна примесь,
ровная местность, без фона/зданий/трансформации, точечные источники.
Нельзя выключать физические эффекты в нашем расчёте и сравнивать с ЭРА,
где они включены. Несовместимый режим — не численное расхождение, а отдельный
неподдержанный сценарий.

## Два разных сравнения

**Фиксированный ветер.** Одинаковые источник, точка, направление и скорость.
Сравниваем Cm/Xm/Um и промежуточные параметры, когда экспорт оригинала их
содержит, затем концентрации и вклады источников. Это проверяет физическое
ядро независимо от оптимизатора. Текущая автоматическая команда проверяет
полную матрицу концентраций; автоматическое сравнение промежуточных
параметров и вкладов предстоит добавить.

**Поиск неблагоприятного ветра.** Сравниваем максимальную концентрацию и
допустимый диапазон ветров. Дополнительно оцениваем нашу модель при ветре,
найденном ЭРА, и просим обратную проверку ЭРА при нашем ветре. Если при
одинаковом ветре значения совпадают, а максимумы различаются, исследуем
поиск и его разрешение. Различие самих азимутов не всегда ошибка:
симметрия и почти плоский максимум допускают несколько близких решений.
Это пока протокол будущей проверки, не выполненная сверка с оригиналом.

## CLI для эталонных задач

```sh
era-engine dispersion-compare reference.json
```

Формат показан в `examples/dispersion-reference.json`:

- `calculation`: обычное задание `dispersion` с фиксированными ветрами.
- `reference`: происхождение, программа, версия, идентификатор задачи,
  настройки и точность экспорта. `kind` — `era_export` только для реальной
  выгрузки ЭРА либо `independent_formula` для независимого расчёта формул.
- `expected_receptors`: все точки в порядке задания, для каждой — все
  концентрации в порядке ветров. Пропуски и несовпадение ID отвергаются.
- `concentration_tolerance`: абсолютный допуск в мг/м³ и относительный
  допуск как доля, например `0.001` означает 0.1%, а не 0.001%.

Условие прохождения: `|Rust − эталон| ≤ abs_tol + rel_tol × |эталон|`.
Допуски согласовываются **до** оценки результата, исходя из точности
выгрузки и задачи; их нельзя увеличивать только ради зелёного теста.
Для близких к нулю концентраций решающим является абсолютный допуск.
Если экспорт округлён, учитывается его шаг округления; разницу меньше этого
шага нельзя трактовать как доказанное преимущество или ошибку алгоритма.
Универсальный процент нормативно допустимой ошибки здесь не задаётся.

Отчёт содержит каждую пару чисел, абсолютное/относительное расхождение,
применённый допуск и итог. Относительная ошибка для нулевого эталона — `null`,
при этом сравнение по абсолютному допуску выполняется. Код выхода 0 означает
совпадение всех значений; при расхождении возвращается JSON и код 1.
Некорректный файл даёт ошибку без отчёта. Необходимо проверять код выхода.
Метка `era_export` — заявление автора файла, не автоматическая проверка
подлинности: оригинальный экспорт и настройки проверяются отдельно.

Учебный пример — независимый расчёт формул, **не результат ЭРА**.
Его прохождение не означает совместимость с ЭРА.

## Набор контрольных задач

Расширяем постепенно: одна тёплая труба; холодные/малоскоростные выбросы;
границы ветвлений; низкие трубы; разные коэффициенты F; прямоугольное устье;
осевые/боковые/наветренные точки; несколько совместно работающих источников;
нулевые и очень малые выбросы. Затем отдельно новые режимы по мере реализации.
Для каждой задачи сохраняются вход, эталон, версия программы и отчёт сравнения.
Ни число тестов, ни одна прошедшая задача не означают перенос всего комплекса.

Пока эталонов нет, используем независимые вычисления формул, проверки
симметрии и линейности, граничных режимов и плотный перебор ветров.
Плотный перебор использует наше же физическое ядро, поэтому проверяет
только поиск, а не правильность физической модели относительно оригинала.
