# Импорты справочных DLL — 19.10.2026

Продолжение [контрольной точки TLS/NLS](CRT_TLS_RESEARCH.md), коммит `3ae49b2`.
Рабочего обхода ключа, оригинального расчёта или нативного запуска Windows
этот этап не подтверждает. Исполняемый релиз не публикуется.

## Установленная причина прежнего перехода

В локальном `grd_crt_tls_23.json` изменённый переход `0x10001c80` читает слот
`0x6b881708` справочной kernel32.dll. Этот слот импортирует
`api-ms-win-core-processthreads-l1-1-0.dll!GetCurrentProcess`. Значение
`0x000a4cb4` в неразрешённой IAT — RVA записи импорта, не действительный
адрес загруженной функции. В оригинальном файле kernel32 её экспорт
GetCurrentProcess тоже начинается с косвенного перехода через этот слот.
Полученные данные согласуются с переносом перехода в первичный образ.

В настоящем процессе привязкой IAT занимается загрузчик. Схема API sets
отделяет имя контракта от конкретной DLL-реализации; простое отображение
PE из файла этого не выполняет.
[PE Format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format),
[API set loader operation](https://learn.microsoft.com/en-us/windows/win32/apiindex/api-set-loader-operation).

## Явный режим маркеров

`--reference-import-markers` требует хотя бы один `--module`. Обычные
импорты справочных образов заменяются в эмулируемой памяти уникальными
маркерами диапазона `0x75000000..0x75100000`, по 16 байт на слот. В отчёте
сохраняются исходный модуль, IAT-адрес, имя импортируемой функции и маркер.
Проверяются границы, повторные слоты, бюджет и пересечения адресов.

Маркеры **не являются реальными адресами функций Windows**. Инструмент
перехватывает вход до исполнения и либо применяет явно поддержанный
контракт, либо завершает трассу с именем неизвестного вызова. Неизвестные
функции не получают нулевого или успешного ответа. Отображённые справочные
образы после настройки снова доступны только для чтения/выборки инструкций;
гостевая запись в IAT запрещена. Исходные файлы не меняются.

Это не полноценный загрузчик: нет привязки delay imports, API-set schema,
переноса образов на другую базу, запуска зависимостей или их кода по адресам
справочных модулей. Код, скопированный самой исследуемой DLL в первичный
образ, отдельно по происхождению не фильтруется; прежняя граница остановки
по адресу справочного модуля на такие копии не распространяется.

## Поддержанные контракты

Для точного имени `api-ms-win-core-processthreads-l1-1-0.dll!GetCurrentProcess`
разрешена уже существующая модель псевдодескриптора текущего процесса.
Принадлежность функции этому контракту указана в официальных
[метаданных Microsoft](https://github.com/MicrosoftDocs/sdk-api/blob/docs/sdk-api-src/content/processthreadsapi/nf-processthreadsapi-getcurrentprocess.md).
Другие имена/версии API sets не перенаправляются автоматически.

Добавлена ограниченная модель DuplicateHandle/CloseHandle, в том числе
точного контракта `api-ms-win-core-handle-l1-1-0.dll`. Разрешено дублирование
только собственного процесса/потока или уже созданного моделью дескриптора,
в тот же процесс и с `DUPLICATE_SAME_ACCESS`. Сохраняются идентичность объекта,
признак наследования и время жизни дескриптора. Неподдержанные флаги, чужие
процессы, неизвестные/закрытые дескрипторы и плохой выходной буфер останавливают
эксперимент без создания записи. Закрытие одного дубликата не завершает поток
и не закрывает остальные дубликаты. Число выданных дескрипторов ограничено 128;
файлы, устройства, лицензии и новые потоки этим не создаются.
[DuplicateHandle](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-duplicatehandle),
[CloseHandle](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-closehandle).

Синтетические тесты проверяют остановку неизвестного импорта до исполнения,
контракт стека, возврат известного API, защиту IAT от записи, неизменность
справочного файла, отсутствие wildcard-алиасов и владение дескрипторами.

## Прогоны

В `grd_reference_iat_01.json` привязаны 6209 обычных слотов импортов десяти
явно переданных справочных DLL. Прежний неверный переход пройден; два
GetCurrentProcess вернули модельный псевдодескриптор. Следующая остановка —
точно `api-ms-win-core-handle-l1-1-0.dll!DuplicateHandle`, на 193 609 222-й
инструкции. Аргументы указывают на дублирование текущего потока в текущем
процессе, выход в `0x1036a4b0`, SAME_ACCESS, без наследования. Attach вернул
`1` на 82 656 831-й инструкции. В этом прогоне модель DuplicateHandle ещё
не была загружена; SHA-256 инструментов отражает эту версию.

В локальной kernel32.dll GetCurrentThreadId читает Self через FS:0x18,
затем идентификатор через смещение 0x24. Для такого кода, перенесённого в
первичный образ, одного перехвата экспортов недостаточно. При совместном
включении `--thread-model --startup-model` только поле 0x24..0x27 теперь
доступно для чтения и содержит тот же thread_id, что и API-профиль. Соседние
поля TEB остаются неизвестными, запись в поле запрещена, без startup-профиля
чтение останавливается как прежде. Согласованность и границы проверены тестами.

В `_02` DuplicateHandle действительно завершился в модели: создан один
неунаследуемый дескриптор текущего потока `0x76000000`. Остановка на
194 662 940-й инструкции — чтение смещения TEB 0x24 перенесённой функцией
по адресу `0x10001b86`. Этот прогон выполнен до добавления поля thread_id;
он отдельно подтверждает необходимость следующего расширения модели.

В `_03` новая модель thread_id включена, но общий лимит 200 млн инструкций
достигнут до повторной проверки конечного участка. Это не повтор прежнего
сбоя и не доказательство завершения подготовки. Для более длинных связанных
сценариев максимальные явные лимиты CLI расширены до 300 млн инструкций и
450 секунд; значения по умолчанию 20 млн/45 секунд не изменены.

На этой контрольной точке проходят 75 синтетических тестов Python. Rust-код
не менялся: ранее в этом этапе прошли все 59 тестов с локальным корпусом.
Хеши кода и отчётов сохранены в [манифесте](research-checkpoint-2026-10-19-iat.json).
Полные отчёты, справочные DLL/NLS и файлы ЭРА не публикуются.
