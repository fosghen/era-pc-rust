# Контрольная точка исследования загрузчика — 19.10.2026

Рабочий обход ключа **не найден**. Оригиналы не изменены; Windows-программа
и её драйверы не запускались. Ни запуск расчётного ядра, ни его независимость
от ключа этим исследованием не подтверждены.

Ниже сохранена **историческая первая точка**. Более поздние наблюдения,
распаковка host `.text`, модельные события/поток и отдельный worker probe:

Статические ориентиры устройства и SDK: [карта transport](GUARDANT_TRANSPORT_MAP.md).

## Что установлено

| Исследуемый путь | Первая наблюдаемая внешняя зависимость | Число инструкций* |
| --- | --- | ---: |
| Точка входа `p_perv.exe` | `GRDVKC32.DLL!GrdPrepare(-1)` | 31 156 019 |
| Точка входа `era.exe` | `GRDVKC32.DLL!GrdPrepare(-1)` | 30 388 197 |
| Отдельный вызов `GrdPrepare(-1)` | `KERNEL32.dll!GetModuleHandleA("Kernel32.dll")` | 43 813 992 |

*Наблюдаемые начала инструкций, без адреса-маркера импорта. Первые два пути
и вызов DLL исследованы **отдельно**, а не в одном полном Windows-процессе.
Для вызовов EXE значение аргумента подтверждено словом `0xffffffff` на стеке.
Повторный прогон расчётного блока достиг того же вызова с теми же аргументами
и числом записей за 31 022 427 инструкций; повтор DLL дал 43 813 992.
Следовательно, воспроизведены внешняя граница и наблюдаемое состояние,
но не доказана идентичность всей последовательности инструкций. Причина
различия счётчиков пока не установлена; точные числа относятся к конкретным
сохранённым прогонам, а не являются обязательным эталоном для любой машины.

До остановки наблюдались записи только в служебные секции:

- `p_perv.exe`: 45 991 событие записи в добавленную `.idata`;
- `era.exe`: 45 991 событие записи в добавленную `.idata`;
- `GrdPrepare(-1)`: 47 940 событий записи в `.grd0001`.

Это события записи, не число уникальных изменённых байтов. Основная `.text`
расчётного блока в наблюдаемом пути не изменялась. Успешная распаковка
расчётных функций и обращение к аппаратному ключу пока не наблюдались.

Уже ранее установлено, что `GrdPrepare` не является булевой проверкой:
отдельные операции возвращают адреса внутренних функций и указатели
`VirtualAlloc`/`VirtualFree`. Две копии `grdvkc32.dll` в поставке имеют один
SHA-256. Подмена одной другой или возврат постоянного «успеха» не обоснованы.

## Границы достоверности

Использован Unicorn, исполняющий x86-инструкции в моделируемой памяти.
Импорты заменены только в этой памяти адресами остановки: API не вызывается
и не получает выдуманного результата. Дисковые EXE/DLL остаются неизменными.
Хеш каждого входа проверяется до и после эксперимента.

Модель не включает Windows loader, PEB/TEB, TLS, инициализаторы зависимостей
и устройство Guardant; страницы образа доступны RWX. Следовательно,
наблюдения не доказывают, что нативный процесс пройдёт точно такой же путь.
Вызов `GetModuleHandleA` — зависимость от среды Windows, а не установленная
проверка лицензии. Нельзя называть достижение этой точки обходом защиты.
Временные инструкции процессора отдельно не фиксируются; полного
детерминированного воспроизведения Windows-среды инструмент не обещает.

Ранние прогоны ограничивались 100 тыс., 2 млн и 5 млн инструкций и заканчивались
по лимиту внутри загрузчика. Продлённые прогоны дали конкретный внешний вызов;
прежняя остановка не была доказательством бесконечного цикла или невозможности
исследования. Ранние отчёты сохранены отдельно, не перезаписаны.

## Воспроизведение

Исследовательский инструмент не является частью пользовательского CLI.
Зависимости отделены в `tools/requirements-research.txt`. Собственные тесты
строят минимальные искусственные PE-файлы и не используют оригинальную ЭРА:

```sh
python -m pip install -r tools/requirements-research.txt
python -m unittest discover -s tools -p 'test_loader_trace.py' -v
python tools/loader_trace.py /path/to/p_perv.exe --max-instructions 50000000 --max-seconds 60 --report /local/evidence/perv.json
python tools/loader_trace.py /path/to/grdvkc32.dll --export GrdPrepare --argument=-1 --max-instructions 50000000 --max-seconds 60 --report /local/evidence/grd.json
python tools/loader_trace.py /path/to/era.exe --max-instructions 50000000 --max-seconds 60 --report /local/evidence/era.json
```

Каталог для отчётов должен существовать. Инструмент отказывается заменять
существующий отчёт. Скорость зависит от машины: достижение лимита времени
не опровергает контрольную точку; при необходимости лимит можно увеличить
до 300 секунд. Нельзя подменять неизвестные данные для получения «успеха».

Отчёт содержит SHA-256 входа и версии инструмента, зависимости, причину
остановки, аргументы внешнего вызова, регистры, диапазоны записей и проверку
неизменности оригинала. Дампы памяти и байты стороннего кода не экспортируются.
`tools/requirements-research.txt` фиксирует версию пакета Capstone 5.0.9;
его внутренняя строка `__version__` в данной установке сообщает 5.0.7.
Новые отчёты явно сохраняют оба источника версии, не смешивая их.

Манифест [research-checkpoint-2026-10-19.json](research-checkpoint-2026-10-19.json)
фиксирует хеши локальных свидетельств и инструментов. Файлы поставки,
локальные полные отчёты и старые фрагменты дизассемблирования в репозиторий
не включены. Манифест позволяет обнаружить изменение, но не заменяет исходные
файлы и не является криптографически подписанным свидетельством.

## Следующий вопрос

Нужно проследить продолжение после получения модуля Kernel32 в корректно
инициализированной изолированной среде и установить первый действительно
используемый результат лицензирования: статус, данные, криптографический
материал или аппаратное вычисление. Этого результата пока нет. Даже будущий
запуск изменённой ЭРА не сделает её автоматически достоверным эталоном для
сравнения с независимым Rust-ядром.
