# Рассеивание: экспериментальный модуль

Независимая реализация части МРР-2017, а не извлечённый код `p_perv.exe`.
Источник формул: приказ Минприроды России от 06.06.2017 №273,
главы IV, V и VIII ([официальная публикация зарегистрированного документа](https://minjust.consultant.ru/documents/36322?items=100)).
Формулы сверены по изображениям страниц документа. Это описание реализации
редакции 2017 года, не утверждение о её актуальности для конкретной отчётности.
Численное совпадение с оригинальной ЭРА пока **не проверено**.

## Запуск

Публичных EXE и ZIP пока нет. Для разработчиков, собравших Windows EXE локально:

```powershell
.\era-engine.exe dispersion .\examples\dispersion.json
```

Из исходников: `cargo run --release --locked -- dispersion examples/dispersion.json`.
Оригинальные программы, базы, USB-ключ и `ERA_DATA` не используются.
Пример полностью синтетический; его коэффициенты не подходят автоматически
для реального предприятия. Интерфейс пока консольный, без редактора проектов.

## Поддержанный расчёт

Вертикальные точечные источники постоянной мощности на ровной местности
(`η=1`), одна примесь, расчёт в приземном слое (высота точки 2 м).
Круглое или прямоугольное устье, положительная скорость выхода, температура
газа не ниже воздуха. Каждая труба имеет свои геометрию, температуру и выброс.
Допустимость совместной работы источников проверяет пользователь.

| Расчёт | Формулы МРР-2017 |
| --- | --- |
| Расход, параметры подъёма, m и n | (4)–(10) |
| Cm: тёплый, холодный и малоскоростные режимы | (3), (11)–(14) |
| Xm и Um | (15)–(19) |
| Поправки на заданную скорость ветра | (20)–(23) |
| Осевое и поперечное распределение, низкие источники | (24)–(29) |
| Эквивалентное круглое устье | (32)–(33) |
| Сумма концентраций при общем ветре | (49) |

При `fe < f < 100` подстановка `fe` производится только при вычислении `m`.
При `ΔT < 0.5` или `f ≥ 100` используется холодная ветвь. При `ΔT=0`
параметр `f` возвращается как `null`, а не бесконечность. Высота трубы ниже
2 м заменяется расчётной высотой 2 м. У прямоугольного устья используется
эквивалентный диаметр `2ab/(a+b)` и соответствующий расчётный расход,
а не объёмный расход через фактическую площадь прямоугольника.

## Поля входного JSON

Все поля обязательны. Неизвестные поля отвергаются, чтобы неподдержанная
настройка не была молча проигнорирована. Имена источников и точек уникальны
внутри своего списка; пустые списки недопустимы.

| Поле | Смысл / единицы |
| --- | --- |
| `pollutant` | Метка примеси, без автоматического поиска в справочнике |
| `coefficient_a` | Положительный климатический коэффициент A, задаёт специалист |
| `air_temperature_c` | Температура воздуха, °C |
| `max_wind_speed_m_s` | Верхняя граница скоростей ветра, м/с; минимум 6 |
| `sources[].id`, `receptors[].id` | Идентификаторы |
| `sources[].x_m`, `y_m` | Местные координаты: X на восток, Y на север, м |
| `sources[].height_m` | Высота трубы над землёй, м, неотрицательная |
| `sources[].outlet` | `{"shape":"circular","diameter_m":1}` либо `{"shape":"rectangular","length_m":2,"width_m":1}` |
| `sources[].exit_velocity_m_s` | Скорость выхода газа, м/с: больше 0, не выше 330 |
| `sources[].gas_temperature_c` | Температура газа, °C: не ниже воздуха, не выше 3000 |
| `sources[].emission_g_s` | Выброс одной примеси, г/с, неотрицательный |
| `sources[].settling_factor` | Коэффициент F, поддержан диапазон 1–3, задаёт специалист |
| `receptors[].x_m`, `y_m`, `height_m` | Координаты в метрах, высота строго 2 м |
| `winds[].from_degrees` | Метеорологический азимут ОТКУДА дует ветер: север=0, восток=90, юг=180 |
| `winds[].speed_m_s` | Скорость на высоте 10 м, от 0.5 до `max_wind_speed_m_s` |

Азимут 360 разрешён как север. Ветер с юга переносит примесь в сторону
увеличения Y. Для каждого источника точка против ветра и плоскость `x=0`
дают нулевой вклад; значение непосредственно в устье не моделируется.
Расстояния от каждой трубы до каждой точки ограничены 100 км.
Защитные ограничения реализации: высота трубы ≤100 км, верхняя скорость
ветра ≤330 м/с, не более 20 млн сочетаний источник–точка–ветер на запрос.
Эти технические границы не означают физическую применимость любого входа.

## Результат

`source_parameters` содержит режим, промежуточные параметры, `cm_mg_m3`,
`xm_m`, `um_m_s`. Это характеристики каждой трубы по формулам; `Cm` —
индивидуальный максимум, не обязательно достигаемый среди заданных ветров.

Для каждой точки `receptors` возвращает концентрации в мг/м³ в порядке
входных ветров, максимум **только по заданным вариантам**, индекс и параметры
этого ветра. `contributions_at_worst_mg_m3` содержит вклады в порядке
входных источников при том же ветре. При равенстве максимумов выбирается
первый вариант. Вклады складываются при общих метеоусловиях; индивидуальные
`Cm` разных труб не суммируются в качестве максимума предприятия.

При ошибке CLI выдаёт сообщение в stderr и ненулевой код выхода, без JSON
результата. Предупреждения о границах применимости входят в каждый результат.

## Проверки и оставшаяся работа

Для синтетической трубы H=30 м, D=1 м, w=10 м/с, Tг=120°C,
Tв=20°C, M=1 г/с, A=200, F=1 независимое вычисление формул с Decimal
(60 знаков) даёт Cm=0.02137663748860852 мг/м³,
Xm=369.73328243265895 м, Um=1.9300544685992504 м/с.
Холодный случай H=10 м, ΔT=0 при остальных тех же параметрах даёт
Cm=0.18617223498965062 мг/м³, Xm=148.2 м, Um=1.3 м/с.
Эти значения — **не эталоны из ЭРА**.

Тестируются ветвления, переходы, направление ветра, боковая симметрия,
линейность по выбросу, суммирование, геометрия устья, низкие трубы и ошибки.
Windows-пакет проходит дополнительный запуск своего EXE на примере.
Общего доказательства корректности или нормативной аттестации это не заменяет.

Пока не реализованы: оптимизация ветра в непрерывном диапазоне, штиль ниже
0.5 м/с, выброс без начальной скорости, газ холоднее воздуха, линейные и
площадные источники, группы суммации, фон и ПДК, трансформация, застройка,
сложный рельеф, повышенные точки, среднегодовые концентрации, обратные
задачи, нестационарность и импорт проектов ЭРА. По умолчанию ничего из этого
не подмешивается в результат. Следующие этапы — расширение модели,
контрольные задачи и удобный Windows-интерфейс.

## Сборка Windows

CI собирает `x86_64-pc-windows-msvc` на Rust 1.90.0 и проверяет упаковку EXE,
примера, инструкции, номера коммита и лицензий зависимостей. Этот пакет
остаётся только в сборочном окружении: загрузка артефактов и публикация
исполняемых файлов отключены до полноценного пользовательского релиза.
Для C runtime
выбрана статическая линковка через `crt-static`
([Rust Reference](https://doc.rust-lang.org/reference/linkage.html#static-and-dynamic-c-runtimes));
системные библиотеки Windows по-прежнему нужны. Пакет не подписан.
Успешный CI на Windows не означает проверку на каждой версии Windows.
