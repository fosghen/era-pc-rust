Расчётное ядро ЭРА на Rust — этап восстановления 2, дополнение 19.10.2026

Это независимый исполнитель восстановленного языка методик. Он не загружает
ERA.EXE, P_PERV.EXE или Guardant и не требует электронного ключа. Исходные
программы поставки не изменены. Полное воспроизведение всего комплекса ещё
не выполнено; границы перечислены ниже.

БЫСТРЫЙ ЗАПУСК ИЗ /mnt/d/era_pc

Готовый исполняемый файл bin/era-engine собран для Linux x86_64 / WSL:

  ERA_DATA=reverse_engineering/recovered era-rust/bin/era-engine run era-rust/examples/washing.json
  ERA_DATA=reverse_engineering/recovered era-rust/bin/era-engine run era-rust/examples/battery_acid.json
  ERA_DATA=reverse_engineering/recovered era-rust/bin/era-engine run era-rust/examples/battery_melting.json
  ERA_DATA=reverse_engineering/recovered era-rust/bin/era-engine run era-rust/examples/fuel_testing.json
  ERA_DATA=reverse_engineering/recovered era-rust/bin/era-engine run era-rust/examples/tire_repair.json

Несколько независимых расчётов в трёх потоках:
  ERA_DATA=reverse_engineering/recovered era-rust/bin/era-engine run-batch era-rust/examples/batch.json 3

Таблицы загружаются один раз, программы разбираются один раз на метод.
У каждого расчёта своё состояние. Порядок результатов совпадает с входным.
Если один расчёт завершился ошибкой, пакет не выдаёт частичный успешный JSON.

СБОРКА

  cargo build --release --manifest-path era-rust/Cargo.toml
  cargo test --manifest-path era-rust/Cargo.toml
  cargo test --manifest-path era-rust/Cargo.toml --features recovered-tests

Обычный cargo test запускает независимые тесты без локальной базы.
Флаг recovered-tests включает дополнительные проверки извлечённых методик.
Путь к базе для них можно задать ERA_DATA. Демонстрация без файлов поставки:
  cargo run --manifest-path era-rust/Cargo.toml -- demo

При обычной сборке исполняемый файл будет era-rust/target/release/era-engine.
Использован Rust 1.90.0. Зависимости зафиксированы в Cargo.lock.
Сборка Windows в этой сессии не проверялась; готовый файл bin/era-engine — ELF,
а не Windows EXE. Программа использует стандартные переносимые API Rust.

ДАННЫЕ

Источник: reverse_engineering/recovered/algorithms.json и tables/*.json,
созданные скриптом recover_methods.py из исходных DBF с проверкой CRC.
ERA_DATA задаёт путь к каталогу recovered. Без него используется путь к данным
рядом с исходным проектом на момент компиляции; при переносе лучше указать ERA_DATA.

ФОРМАТ ЗАДАНИЯ

method: четырёхзначный код метода, например "0092".
inputs: значения переменных, запрашиваемых пустой графой формулы. Имена
  регистронезависимы, числа остаются числами, словарные коды — строками.
selections: очереди номеров строк для интерактивного TAB, ключ — номер строки
  алгоритма. Например "16":[1] выбирает первую строку таблицы при выполнении
  строки 16 алгоритма 0092. Номер выбора внутри словаря/таблицы начинается с 1.
prompts: очереди значений по номеру строки для циклов и подтверждения формул.
  Например в 0086 "51":[1,0] повторяет расчёт для второго типа батареи, а
  "32":[60,100] задаёт разные ёмкости при двух проходах. Для второго прохода
  необходимо также предоставить второй выбор электролита: "27":[1,2].
initial: дополнительные параметры проекта/города, которые читает алгоритм,
  например "ngor.kno_". Неизвестные переменные не подменяются нулями.
trace: сохранять ли значения переменных с номерами строк и записей DBF.
max_steps: предел выполнения, по умолчанию 100000, для обнаружения циклов.

Выход variables содержит конечное состояние переменных, writes — события
присваивания _M_ и _G_ с кодом вещества и номером строки. writes НЕ является
готовой суммой выбросов по проекту. Запись в DBF проекта, накопление по _Saf_,
_MaxG_, очистка и перезапись источников ещё не эмулируются.

ПОДДЕРЖАНО И ПРОВЕРЕНО

Проверены последовательные пути в 0092, 0086, 0093 и 0087:
  — все пять строк коэффициентов мойки 0092;
  — оба электролита, повторный проход и ветвь плавления 0086;
  — оба коэффициента испытаний и ветвь мойки 0093;
  — ветвь шероховки шин 0087.
Выбранные формулы 0074 проверены по независимому PDF-протоколу поставки.
Не все ветви этих методов покрыты тестами. Весь 0074 пока не исполняется:
в исходных данных обнаружена неоднозначная повторяющаяся метка.

Исполнитель поддерживает числа f64, строки, логические выражения, арифметику,
ЕСЛИ, ШАГ с постоянной/переменной меткой, КОНЕЦ, множественные присваивания,
STORE, DIMENSION, двумерные системные массивы, часть функций FoxPro,
пользовательские массивы, линейные индексы, _ASUM/_AMAX по строке/колонке,
TAB по номеру/выбору/предикату, словари и именованные колонки.
STORE и DIMENSION принимают несколько целей. Изменение размерности сохраняет
элементы в линейном порядке, новые элементы получают .F.; STORE в имя массива
заполняет весь массив (семантика FoxPro SET COMPATIBLE OFF).
Переменная Or в формулах топлива больше не конфликтует с логическим OR.

TAB поддерживает неявное сравнение со словарными кодами и колонку отметки 21.
Фильтр без начального номера требует явного выбора через selections; выбор
строки, не удовлетворяющей фильтру, отклоняется. Положительный начальный номер
означает первое совпадение начиная с этой строки, как описано в руководстве.
Для словаря _Row_ теперь содержит физический номер записи DBF; выражение,
непосредственно использующее _Row_, трактуется в физических номерах, прочие
числовые селекторы — в порядковых. Сложная навигация по разреженным словарям
и порядок словарного индекса оригинала ещё требуют проверки на оригинале.
Операторы переходов исполняются по исходным строкам, а не заменены отдельными
заранее выписанными формулами.

НЕ ПОДДЕРЖАНО / НЕ ПОДТВЕРЖДЕНО

Полная семантика FoxPro и весь язык ЭРА не реализованы. В частности:
  — часть вариантов поиска TAB, выбор нескольких строк, диапазоны;
  — часть функций массивов и режим FoxPro SET COMPATIBLE ON;
  — функции интерфейса и проекта: INDLL, YES, VMENU, INIT и другие;
  — адаптивное округление _Toch_/_MinT_; сейчас вычисления raw f64;
  — проектные DBF, суммирование и очистка выбросов, автоматическое восстановление
    _M_/_G_ при переключении вещества;
  — протоколы PITOG: вместо печати сохраняется явное примечание;
  — семь однострочных заглушек и защищённый расчёт рассеивания P_PERV.EXE.

Неизвестный вызов или неоднозначная метка приводит к ошибке с методом, строкой
и записью DBF. Прохождение синтаксического анализа не означает, что метод
исполняется полностью. TAB разбирается подробно во время выполнения.

ПРОВЕРКИ И ПРОИЗВОДИТЕЛЬНОСТЬ

  python3 reverse_engineering/validate_rust.py --binary era-rust/bin/era-engine
  python3 reverse_engineering/benchmark_rust.py --binary era-rust/bin/era-engine
  era-rust/bin/era-engine audit

Результаты: reverse_engineering/rust_validation.txt, rust_sample_results.json,
rust_batch_results.json, rust_syntax_audit.json, rust_benchmark.json.

Микротест сравнивает только две формулы метода 0092. Файловый ввод и разбор
программ исключены. Сравнение с Python-прототипом включает выигрыш от разбора
формул заранее; это не чистый коэффициент ускорения языка. Дополнительно
измеряется непосредственная арифметика Python и Rust. Ускорение всей ЭРА и
расчёта рассеивания не измерялось. Многопоточное ускорение пока не измерялось:
для маленьких заданий накладные расходы потоков могут оказаться существенными.
