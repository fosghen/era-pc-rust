# ЭРА ПК на Rust — `era-pc-rust`

[![Rust CI](https://github.com/fosghen/era-pc-rust/actions/workflows/ci.yml/badge.svg)](https://github.com/fosghen/era-pc-rust/actions/workflows/ci.yml)

Независимый экспериментальный проект на Rust для исследования расчётов выбросов
и рассеивания в предметной области ПК ЭРА. Проект не связан с разработчиком
оригинальной программы и пока не является её полной заменой или проверенным
нормативным ПО.

Текущая версия пакета — **`0.2.0-alpha.1`**. Основной интерфейс — CLI с JSON
на входе и выходе. Оконный GUI не планируется.

## Что входит в проект

В репозитории развиваются три связанных, но самостоятельных направления:

1. **Независимый модуль рассеивания.** Реализует ограниченную часть расчётов
   для вертикальных точечных источников по опубликованным формулам МРР-2017.
   Для него не нужны файлы, EXE, DLL или ключ оригинальной ЭРА.
2. **Исполнитель восстановленного языка методик.** Загружает локальную
   JSON-модель извлечённых алгоритмов и таблиц, разбирает выражения и выполняет
   поддержанные пути методик. Эти команды требуют локальных данных через
   `ERA_DATA`; сами данные в репозиторий не входят.
3. **Инструменты исследования и валидации.** Сравнивают расчёты с сохранёнными
   отчётами проектов, проверяют происхождение входов, воспроизводят отдельные
   поля и исследуют запуск защищённых компонентов. Это исследовательские
   инструменты, а не функции готового пользовательского продукта.

## Быстрый старт

Нужен Rust **1.90.0**. Зависимости зафиксированы в `Cargo.lock`.

```sh
git clone https://github.com/fosghen/era-pc-rust.git
cd era-pc-rust
cargo test --locked
cargo run --locked -- demo
cargo run --release --locked -- dispersion examples/dispersion.json
```

`demo` выполняет учебный расчёт 1 г/с и 3,6 т за 1000 часов. Это проверка
исполнителя, а не нормативная методика.

### Команды CLI

| Команда | Назначение | Нужен `ERA_DATA` |
| --- | --- | :---: |
| `demo` | Автономная демонстрация интерпретатора | Нет |
| `dispersion FILE` | Концентрации для заданных источников, точек и ветров | Нет |
| `dispersion-search FILE` | Поиск неблагоприятного ветра по уточняемым сеткам | Нет |
| `dispersion-compare FILE` | Сравнение матрицы концентраций с эталоном и допусками | Нет |
| `run FILE` | Выполнение одной восстановленной методики | Да |
| `run-batch FILE [WORKERS]` | Независимые пакетные расчёты с сохранением порядка | Да |
| `audit` | Аудит разбора строк и внешних вызовов локальной базы | Да |
| `bench [ITERATIONS]` | Узкий микротест двух формул метода 0092 | Да |

Полная подсказка доступна через:

```sh
cargo run --locked -- --help
```

## Независимый модуль рассеивания

Сейчас реализованы:

- одна примесь и один или несколько вертикальных точечных источников;
- круглые и прямоугольные устья;
- тёплая и поддержанная холодная/изотермическая ветви;
- параметры `Cm`, `Xm`, `Um`;
- приземные концентрации в заданных точках при заданных скоростях и
  направлениях ветра;
- сумма вкладов нескольких источников;
- поиск ветра по уточняемым сеткам с историей улучшений, лимитом вычислений
  и явным статусом остановки;
- сравнение полной матрицы концентраций с эталоном по заранее заданным
  абсолютному и относительному допускам.

Коэффициенты `A` и `F` задаёт пользователь. Координаты указываются в метрах:
X направлена на восток, Y — на север; направление ветра задаётся **откуда**
он дует. Выброс задаётся в г/с, концентрация возвращается в мг/м³. Расчётная
высота рецептора сейчас фиксирована на 2 м.

Формат JSON, единицы, проверки входа и область применимости описаны в
[docs/DISPERSION.md](docs/DISPERSION.md).

## Исполнитель методик

Исполнитель поддерживает числа, строки и логические значения; арифметику,
условия, переходы и циклы; таблицы и словари; явный выбор строк и поиск по
условиям; диапазоны TAB и `_Diap_`; массивы, групповые присваивания, суммы и
максимумы; трассировку и диагностические сообщения с методом, строкой и
номером записи.

Локально проверены отдельные пути методов `0092`, `0086`, `0093`, `0087` и
отдельные формулы `0074`. Это не означает полного исполнения этих методик или
всего языка. Неизвестные функции, неподдержанные побочные эффекты и
неоднозначные метки завершаются явной ошибкой, а не заменяются догадками.

Для локального корпуса:

```sh
export ERA_DATA=/absolute/path/to/recovered
cargo run --release --locked -- run examples/washing.json
cargo run --release --locked -- run-batch examples/batch.json 3
cargo run --release --locked -- audit
cargo test --locked --features recovered-tests
```

В PowerShell:

```powershell
$env:ERA_DATA = 'C:\path\to\recovered'
```

`recovered-tests` — явное включение тестов локального корпуса. Без базы они
завершаются ошибкой и не пропускаются незаметно. Обычный CI этот режим не
включает. Формат сценариев и подробности семантики собраны в [README.txt](README.txt).

## Что уже проверено

Проект различает несколько уровней доказательности: синтаксический разбор,
исполненный путь, независимую проверку формулы, сравнение с сохранённым отчётом
и контролируемое сравнение с работающей оригинальной программой. Они не
считаются взаимозаменяемыми.

- Основное Rust-ядро покрыто модульными и интеграционными тестами.
- Сохранённые таблицы нескольких частных проектов использованы для строгих
  сравнений `Cm/ПДК`, `Um` и `Xm`; неподдержанные случаи исключаются с явной
  причиной, а не засчитываются как успех.
- В одном наборе 33 из 33 допустимых пар «вещество–источник» совпали по трём
  параметрам при скорости, восстановленной из согласованного расхода и
  диаметра. Это 19 уникальных физических конфигураций, а не 33 проекта.
- Два сохранённых одноисточниковых поля воспроизведены диагностически на всех
  20 402 точках. Исследование выявило чувствительность к представлению
  координат и округлению ветра, но намеренно не объявлено полноценной
  валидацией поля.
- Отдельно исследованы сохранённые архивы, дополнительные наборы проектов,
  отрицательные разности температур и вспомогательные параметры площадных
  источников. Диагностические гипотезы не включаются в производственное ядро
  без самостоятельного обоснования и тестов.

Оригинальная программа не запускалась в этих пакетных исследованиях, а
сохранённые результаты могут не соответствовать текущему состоянию проектов.
Нового контролируемого набора эталонов от лицензированной ЭРА пока нет.
Поэтому совпадение с оригиналом во всех режимах **не подтверждено**.

- [дополнительная подборка проектов](docs/PROJECT_BATCH_VALIDATION.md);
- [пакет заменяющих проектов](docs/REPLACEMENT_PROJECT_VALIDATION.md);

## Ограничения

Сейчас не реализованы или не подтверждены:

- линейные и полноценные площадные источники;
- застройка, сложный рельеф, фон и трансформация веществ;
- группы суммации в полном расчётном процессе;
- среднегодовые концентрации, обратные задачи и остальные модели ЭРА;
- гарантированный непрерывный глобальный максимум по ветру;
- полная семантика FoxPro и языка методик ЭРА;
- функции интерфейса и проекта, включая часть `INDLL`, `YES`, `VMENU`, `INIT`;
- проектные DBF, окончательное накопление, очистка и перезапись выбросов;
- все правила округления и совместимость со всеми вариантами исходных данных;
- загрузка проекта оригинальной ЭРА как готовый пользовательский workflow.

`writes` в результате интерпретатора — события присваивания, а не готовая
инвентаризация выбросов. Поиск ветра имеет критерий устойчивости сетки, но он
не доказывает достижение непрерывного глобального максимума.

Не используйте экспериментальные результаты для официальной отчётности без
независимой профессиональной проверки.

## Windows

Публичных EXE и GitHub Releases пока нет. CI собирает Windows x64 EXE,
формирует ZIP, запускает численный smoke-test точного бинарника и затем не
выгружает артефакт. Локально пакет можно собрать так:

```powershell
rustup toolchain install 1.90.0 --profile minimal
cargo +1.90.0 build --release --locked --target x86_64-pc-windows-msvc
.\scripts\package-windows.ps1
```

Скрипт создаёт ZIP и SHA-256 в `dist`, добавляет примеры, документацию,
`BUILD.txt` и лицензии зависимостей. Это сборочный механизм, а не разрешение
на публикацию предварительного продукта. Критерии релиза перечислены в
[разделе «Публикация»](docs/ROADMAP.md#публикация).

## Структура репозитория

| Путь | Содержание |
| --- | --- |
| `src/` | CLI, интерпретатор, модуль рассеивания, сравнение и поиск ветра |
| `tests/` | Интеграционные тесты CLI, ядра, диапазонов и рассеивания |
| `examples/` | JSON-примеры и исследовательские Rust-команды |
| `docs/` | Спецификации, валидация, roadmap и журналы исследований |
| `tools/` | Ограниченные Python/JS/PowerShell-инструменты анализа и их тесты |
| `packaging/` | Материалы пользовательского Windows-пакета |
| `scripts/` | Сборка и проверка локального Windows ZIP |

Инструменты исследования загрузчика, PE, TLS/FLS, системных API и связанного
старта оригинальных компонентов не входят в расчётный CLI. Их выводы и границы
зафиксированы в отдельных документах, начиная с
[PROTECTION_RESEARCH.md](docs/PROTECTION_RESEARCH.md) и продолжая в
[HOST_LINKED_RESEARCH.md](docs/HOST_LINKED_RESEARCH.md). Рабочего обхода ключа
и подтверждённого запуска защищённого ядра нет.

## План развития

Полный актуальный чек-лист находится в
**[docs/ROADMAP.md](docs/ROADMAP.md#ближайшие-задачи)**. Ближайшие направления:

1. Получить контролируемые эталоны ЭРА и отделить расхождения ядра от поиска ветра.
2. Реализовать остальные типы источников и режимы главы V.
3. Добавить фон, суммацию, трансформацию, рельеф и застройку.
4. Расширить расчёты на среднегодовые и обратные задачи.
5. Довести Windows CLI до полного цикла: импорт, проверка, проекты, пакетный
   расчёт, просмотр и экспорт.
6. Восстановить оставшуюся семантику языка и проектные побочные эффекты.

## Разработка и CI

Перед отправкой изменений:

```sh
cargo +1.90.0 fmt --check
cargo +1.90.0 clippy --locked --all-targets -- -D warnings
cargo +1.90.0 test --locked
python3 -m unittest discover -s tools -p 'test_*.py' -v
node tools/test_native_api_observer.js
```

GitHub Actions выполняет Rust-проверки на Linux, Windows и macOS, а тесты
исследовательских инструментов — на синтетических данных. Успешный CI
подтверждает воспроизводимость этих проверок, но не нормативную корректность
или эквивалентность всей ПК ЭРА.

## Данные, происхождение и лицензия

В репозитории нет установщика оригинальной ЭРА, её EXE/DLL, алгоритмических
баз, ключей, секретов, руководств стороннего продукта или частных проектных
данных. Публично хранятся собственный код, синтетические fixtures, агрегированные
выводы и контрольные хеши без раскрытия исходных проектов.

Публичная лицензия для этого репозитория пока не выбрана. Доступность исходного
кода не означает предоставления лицензии на него или на материалы стороннего
продукта.
